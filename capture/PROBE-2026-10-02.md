**Purpose (as prepared).** Step 25 was the audit's one operator FLAG: on 2026-09-11 the server accepted and settled
targets up to 500,000×, and the only later probe above 10,000× (2026-09-26, one request at 93,830.94×)
did not settle but its reply was not saved. The RTP-CLAIM PASS on targets up to 10,000× holds for the
game only if the server refuses targets from **100,101.12×** up (the first target more than 0.10 points
below the 99% claim). This probe asks the server for four such targets and **saves every reply**.

**Cost.** One $0.10 control bet that settles (expected loss about $0.10) and four $0.10 requests that
cost nothing if refused. At most $0.50 if the server accepted everything.

## Prerequisites

1. Terminal in the package root (`limbo/`). Node 22 (`node --version`), Python 3 with `curl_cffi`
   (`pip3 install curl_cffi` — qa.liqd.com checks the TLS fingerprint, the same transport as the
   2026-09-26 runs, `capture/req-v2.py`).
2. Logged in to `https://qa.liqd.com` in Chrome with **only Limbo open** on the account, no game in
   progress, and at least $0.50 USDC. The probe rotates the account's provably-fair seed (it reads the
   active seed and rotates it before the first bet, as every capture here does), so nothing else may use
   the account while it runs.
3. The session cookie, kept out of history and out of every file: in DevTools → Network, copy any
   `qa.liqd.com/api/v1` request as cURL and take the value of its `Cookie:` header. Then:

   ```sh
   read -rs LIQD_COOKIE && export LIQD_COOKIE    # paste the Cookie header value, press Enter (nothing is echoed)
   ```

   The script passes the cookie to the transport through the environment only (never argv, never a
   file). Every journal line is scrubbed of secret-looking keys and checked against the cookie's own
   values and a JWT pattern before it is written; a hit aborts the write.

## Commands

```sh
node capture/capture-limbo-v2.mjs --cap-probe --plan   # prints the five requests; no network
node capture/capture-limbo-v2.mjs --cap-probe          # runs them (5 place-bet requests, 2 rotations)
unset LIQD_COOKIE
```

Since 2026-10-02 every place-bet body carries `stakeCurrency` (default `USDC`, `--stake-currency=…` to change
it): the API refuses a body without it (run 1 above).

Do **not** use `--resume` with `--cap-probe` (the script refuses it). If the run stops, start it fresh:
a refused request costs nothing, and a fresh run re-anchors its own seed.

Output goes to `capture/out/` (gitignored): `liqd-limbo-cap-probe-<timestamp>.journal.ndjson` (the
record) and `.json` (a view rebuilt from it).

## What proves the cap

The script prints a `CAP RE-PROBE RESULT` block. **Done** means:

```
  control 10000×: accepted, served R …, recomputed R … OK
  100101.12×: REFUSED — HTTP …, errorCode …, "…"; nonce consumed no; reply saved OK
  497487.44×: REFUSED — …; nonce consumed no; reply saved OK
  500000×: REFUSED — …; nonce consumed no; reply saved OK
  990000.01×: REFUSED — …; nonce consumed no; reply saved OK
```

In the journal, for each of the four targets: one `intent` at stake `0.10000000`, a `reply` event with
the HTTP status and the server's body (a refusal is a status of 400 or more, or a body with an `errors`
array — what LIQD actually returns is exactly what this run will record), a `refusal` event with `nonceConsumed: false`,
and **no** `bet`. The control has a `bet`, and the rotation after it reveals the seed it recomputes from.

**If any target line says ACCEPTED**, the server still accepts that target. For 100,101.12×, 497,487.44×
or 990,000.01× that means the 99% claim fails the RTP-CLAIM rule as stated: LIQD would have to cap the
API or state an RTP range. Step 25 stays a FLAG and prints the accepted target; widening the scored range
(`LIVE_TARGET_CEILING`) is then a decision, not an automatic consequence.
